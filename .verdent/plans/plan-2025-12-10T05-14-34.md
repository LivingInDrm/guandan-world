### 5. 实现 renderPlayer 函数

**位置**：TributeBoard 组件内部

**逻辑**：

```typescript
const renderPlayer = (player: Player | null, position: PlayerPosition, seat: number) => {
  // 过滤掉 bottom 位置（与 GameBoard 一致）
  if (position === 'bottom') {
    return null;
  }

  const isGiverRole = isGiver(seat);
  const isReceiverRole = isReceiver(seat);
  const role = isGiverRole ? 'giver' : isReceiverRole ? 'receiver' : null;
  const isCurrentSelector = currentSelectingSeat === seat;

  return (
    <PlayerCard
      player={player}
      position={position}
      isHighlighted={isCurrentSelector}
      statusSlot={
        role ? (
          <TributeRoleBadge
            role={role}
            isSubmitted={hasSubmitted(seat)}
            isReceived={hasReceived(seat)}
            isCurrentSelector={isCurrentSelector}
          />
        ) : undefined
      }
    />
  );
};
```

**关键点**：

- **过滤 bottom 位置**：`if (position === 'bottom') return null`
- 角色判断：isGiver / isReceiver
- statusSlot 注入 TributeRoleBadge

## 飞牌动画处理

### 当前玩家位置的坐标计算

**问题**：bottom 位置不渲染 PlayerCard，但飞牌动画仍需要坐标

**解决方案**：保持 `getPositionForSeat` 函数不变

**原理**：

- `getPositionForSeat` 在 `relativeSeat === 0` 时返回 `{ x: boardRect.left + boardRect.width / 2, y: boardRect.bottom - 40 }`
- 该坐标位于牌桌底部中央偏上 40px 位置
- 虽然不显示 PlayerCard，但飞牌动画仍可飞到该位置
- 视觉上合理：卡片飞向牌桌底部区域（PlayerHand 在下方）

**无需修改**：

- `getPositionForSeat` 函数保持不变（第192-233行）
- `CardFlyAnimation` 调用保持不变
- WebSocket 事件监听保持不变

## 关键设计决策

### 决策1：过滤 bottom 位置（与 GameBoard 一致）

**原因**：

- 统一两个组件的玩家渲染逻辑
- 当前玩家信息通过 PlayerHand 展示，无需重复
- 简化视觉布局

### 决策2：使用 TeamLevelDisplay

**原因**：

- 进贡阶段仍属于同一局游戏，应显示等级信息
- 贡牌类型信息（双下/单下）不如等级信息重要
- 复用 GameBoard 的组件，保持一致性

### 决策3：飞牌动画坐标保持不变

**原因**：

- `getPositionForSeat` 计算的底部坐标仍然合理
- 无需修改飞牌动画逻辑
- 视觉效果自然：卡片飞向牌桌底部区域

### 决策4：创建独立的 TributeRoleBadge 组件

**原因**：

- 角色标识是 Tribute 场景特有的业务逻辑
- 提取为组件便于复用和维护
- 通过 statusSlot 注入，保持 PlayerCard 的通用性
